# 🧠 Mini NPU Simulator (MAC 연산 및 패턴 판별 시뮬레이터)

AI 전용 칩인 **NPU(Neural Processing Unit)**의 핵심 연산인 **MAC(Multiply-Accumulate, 곱셈-누적 덧셈)** 원리를 외부 라이브러리(`NumPy` 등) 없이 순수 Python 반복문으로 직접 구현한 콘솔 시뮬레이터입니다. 필수 요구사항(데이터 구조, 모드 1 사용자 입력 검증, 모드 2 `data.json` 스키마 검증 및 라벨 정규화, `epsilon` 기반 부동소수점 비교 정책, 크기별 성능 분석)과 함께 **보너스 과제 2종(1차원 배열 메모리 접근 최적화, N×N 패턴 자동 생성기)**까지 모두 구현되어 있습니다.

## 2. 구현 요약

1. **데이터 구조 (`Grid2D` 클래스)**
   - `n×n` 크기의 2차원 배열을 캡슐화하여 저장하며, `get(row, col)`과 `set(row, col, value)` 메서드로 특정 위치의 값을 안전하게 읽고 쓸 수 있습니다.
   - 생성 시 행 개수, 각 행의 열 개수, 원소의 숫자(`float`) 변환 가능 여부를 엄격히 검증하며, 최소 `3×3`, `5×5`, `13×13`, `25×25` 및 임의의 `N×N` 크기를 모두 지원합니다.
2. **라벨 정규화 (`normalize_label` 함수)**
   - 프로그램 내부의 표준 라벨을 **`Cross`**와 **`X`** 두 가지로 통일했습니다.
   - `data.json`의 `filters` 키(`"cross"` → `"Cross"`, `"x"` → `"X"`)와 `patterns`의 `expected` 값(`"+"` → `"Cross"`, `"x"` → `"X"`, 대소문자 및 공백 무시)을 모두 표준 라벨로 변환한 뒤 판정 및 `PASS`/`FAIL` 비교를 수행합니다.
3. **MAC 연산 직접 구현 (`mac_compute_2d` & `mac_compute_1d`)**
   - `NumPy` 등 벡터화 라이브러리를 일절 사용하지 않고, 중첩 `for` 반복문을 통해 동일 위치 `(r, c)`의 패턴 값과 필터 값을 곱하고 누적 합산(`total += pattern.get(r, c) * filter_grid.get(r, c)`)하여 `float` 점수를 반환합니다.
4. **점수 비교 정책 (`compare_scores`, 허용오차 $\epsilon = 10^{-9}$)**
   - 이진 부동소수점(IEEE 754) 연산에서 발생하는 미세한 표현 오차가 판정을 왜곡하지 않도록 `EPSILON = 1e-9` 기준을 적용했습니다.
   - `abs(score_a - score_b) < 1e-9`이면 두 점수를 실질적인 동점으로 간주하여 모드 1에서는 `"판정 불가 (|A-B| < 1e-9)"`, 모드 2에서는 `"UNDECIDED"`로 판정합니다.
5. **보너스 과제 구현 (1차원 배열 최적화 & 패턴 생성기)**
   - **메모리 접근 최적화**: 2차원 배열(`N×N`)을 길이 $N^2$인 1차원 리스트(`to_1d_list()`)로 평탄화(flatten)하여 단일 루프와 1회 인덱싱만으로 MAC 연산을 수행하는 `mac_compute_1d()`를 구현하고 성능 향상률을 측정했습니다.
   - **패턴 생성기**: 임의의 크기 `N`에 대해 중심 행·열(`mid = N // 2`)을 `1.0`으로 채우는 `generate_cross_pattern(n)`과 양 대각선(`r == c` 또는 `r + c == N - 1`)을 `1.0`으로 채우는 `generate_x_pattern(n)`을 구현해 모드 1, 성능 분석, 보너스 모드에서 재활용했습니다.

## 3. 결과 리포트 (실패 원인 분석 및 시간 복잡도 분석)

### 3.1 `data.json` 테스트 결과 요약 및 실패 원인 정밀 분석

공식 `data.json` 분석 모드(모드 2)를 실행한 결과, **총 6개 테스트 중 통과(PASS) 3개(`size_5_2`, `size_13_1`, `size_25_2`), 실패(FAIL) 3개(`size_5_1`, `size_13_2`, `size_25_1`)**가 기록되었습니다.

| 케이스 ID | 입력 패턴 형태 | Cross 점수 | X 점수 | 판정 | expected (정규화) | 결과 및 사유 |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **`size_5_1`** | 5×5 X 패턴 | `0.9000000000000000` | `0.8999999999999999` | `UNDECIDED` | `X` (`"x"`) | **FAIL (동점 규칙)** |
| **`size_5_2`** | 5×5 Cross 패턴 | `8.9` | `0.1` | `Cross` | `Cross` (`"+"`) | **PASS** |
| **`size_13_1`** | 13×13 X 패턴 | `0.3` | `14.7` | `X` | `X` (`"x"`) | **PASS** |
| **`size_13_2`** | 13×13 Cross 패턴 | `7.4999999999999973` | `7.5000000000000000` | `UNDECIDED` | `Cross` (`"+"`) | **FAIL (동점 규칙)** |
| **`size_25_1`** | 25×25 X 패턴 | `4.9000000000000004` | `4.8999999999999986` | `UNDECIDED` | `X` (`"x"`) | **FAIL (동점 규칙)** |
| **`size_25_2`** | 25×25 Cross 패턴 | `52.9` | `0.1` | `Cross` | `Cross` (`"+"`) | **PASS** |

시뮬레이터에서 발생한 결과를 **"① 데이터/스키마(라벨·가중치) 문제 vs ② 로직 문제 vs ③ 수치 비교(부동소수점) 문제"**의 3단계로 분리하여 진단한 상세 원인은 다음과 같습니다.

1. **스키마 및 라벨 불일치 문제 해결 (`size_5_2`, `size_13_1`, `size_25_2`가 PASS한 이유)**
   - `data.json` 내부에서 필터 키는 소문자 `"cross"`, `"x"`로 정의되어 있는 반면, 각 패턴의 `expected` 값은 기호 `"+"`, `"x"`로 기록되어 있습니다.
   - 만약 라벨 정규화(`normalize_label`) 과정 없이 원시 문자열을 그대로 비교했다면, `"Cross" != "+"` 및 `"X" != "x"`가 되어 정상 판정된 케이스까지 **6개 전부가 FAIL**로 처리되었을 것입니다.
   - 본 시뮬레이터는 로드 단계에서 모든 라벨을 표준 라벨(`Cross`, `X`)로 정규화하고, 패턴 키(`size_{N}_{idx}`)에서 추출한 $N$과 필터/패턴의 행·열 크기($N \times N$)를 검증했기 때문에 스키마/라벨 표기 차이로 인한 실패를 완벽히 방지했습니다.

2. **실패 케이스 3건(`size_5_1`, `size_13_2`, `size_25_1`)의 근본 원인 1: 필터 중심점 가중치 설계로 인한 수학적 동점**
   - **`size_5_1` (5×5 X 패턴 입력)**: `size_5.x` 필터는 X 대각선 9개 칸의 가중치가 모두 `0.1`이므로 이론적 X 점수는 $9 \times 0.1 = 0.9$입니다. 그런데 `size_5.cross` 필터의 중심점 `(2, 2)` 가중치가 `0.9`로 설정되어 있어, X 패턴과 중심점 1칸만 겹쳐도 Cross 점수가 $1.0 \times 0.9 = 0.9$가 되어 **수학적으로 두 점수가 정확히 `0.9`로 동점**이 됩니다.
   - **`size_13_2` (13×13 Cross 패턴 입력)**: `size_13.cross` 필터는 십자가 25개 칸의 가중치가 모두 `0.3`이므로 이론적 Cross 점수는 $25 \times 0.3 = 7.5$입니다. 그런데 `size_13.x` 필터의 중심점 `(6, 6)` 가중치가 `7.5`로 설정되어 있어, Cross 패턴과 중심점 1칸만 겹쳐도 X 점수가 $1.0 \times 7.5 = 7.5$가 되어 **수학적으로 두 점수가 정확히 `7.5`로 동점**이 됩니다.
   - **`size_25_1` (25×25 X 패턴 입력)**: `size_25.x` 필터는 X 대각선 49개 칸의 가중치가 모두 `0.1`이므로 이론적 X 점수는 $49 \times 0.1 = 4.9$입니다. 그런데 `size_25.cross` 필터의 중심점 `(12, 12)` 가중치가 `4.9`로 설정되어 있어, X 패턴과 중심점 1칸만 겹쳐도 Cross 점수가 $1.0 \times 4.9 = 4.9$가 되어 **수학적으로 두 점수가 정확히 `4.9`로 동점**이 됩니다.

3. **실패 케이스 3건의 근본 원인 2: IEEE 754 부동소수점 누적 오차와 `epsilon`($10^{-9}$) 비교 정책의 핵심 역할**
   - 수학(10진수)적으로는 위 3개 케이스 모두 두 필터 점수가 완전히 같지만(`0.9 == 0.9`, `7.5 == 7.5`, `4.9 == 4.9`), 컴퓨터의 64비트 이진 부동소수점(IEEE 754 `float`)에서는 `0.1`과 `0.3`을 순환 이진소수로 근사 저장합니다.
   - 그 결과 MAC 연산에서 반복 누적 덧셈을 수행할 때 미세한 오차가 누적됩니다:
     - `size_5_1`: `0.1`을 9번 더한 값 = `0.8999999999999999` vs 단일 곱셈 `0.9` = `0.9000000000000000` (차이: $1.11 \times 10^{-16}$)
     - `size_13_2`: `0.3`을 25번 더한 값 = `7.4999999999999973` vs 단일 곱셈 `7.5` = `7.5000000000000000` (차이: $2.66 \times 10^{-15}$)
     - `size_25_1`: `0.1`을 49번 더한 값 = `4.8999999999999986` vs 단일 곱셈 `4.9` = `4.9000000000000004` (차이: $1.78 \times 10^{-15}$)
   - **만약 허용오차(`epsilon = 1e-9`) 정책 없이 단순 대소 비교(`>` / `<`)를 사용했다면**, 누적 덧셈을 한 쪽의 값이 미세하게 작아져서 `size_5_1`(X 패턴)은 `Cross`로, `size_13_2`(Cross 패턴)는 `X`로, `size_25_1`(X 패턴)은 `Cross`로 **3건 모두 정반대 클래스로 잘못 판정(오분류)하는 치명적인 오류**가 발생했을 것입니다.
   - 본 시뮬레이터는 `abs(score_cross - score_x) < 1e-9` 비교 정책을 통해 $10^{-16} \sim 10^{-15}$ 수준의 차이가 부동소수점 표현 오차임을 정확히 걸러내어 `UNDECIDED`(동점)로 판정했으며, 동점 규칙에 따라 `FAIL (동점 규칙)`로 안전하게 리포트했습니다.

### 3.2 크기별 성능 측정 결과 및 시간 복잡도 $O(N^2)$ 분석

I/O 시간을 제외하고 순수 MAC 연산 함수 호출 구간을 각 크기별로 10회 반복 측정한 평균 실행 시간과 연산 횟수($N^2$)는 아래와 같습니다.

| 크기 ($N \times N$) | 연산 횟수 ($N^2$) | 2D 배열 평균 시간 (ms) | 1D 최적화 평균 시간 (ms) | 1D 최적화 속도 향상률 |
| :---: | :---: | :---: | :---: | :---: |
| **3×3** | 9 | 0.0021 ms | 0.0005 ms | +73.7% |
| **5×5** | 25 | 0.0051 ms | 0.0008 ms | +83.4% |
| **13×13** | 169 | 0.0316 ms | 0.0046 ms | +85.4% |
| **25×25** | 625 | 0.1226 ms | 0.0193 ms | +84.3% |

1. **시간 복잡도 $O(N^2)$의 이론적·실험적 근거**
   - $N \times N$ 크기의 2차원 패턴과 필터에 대해 MAC 연산을 수행하려면, 행 방향 $N$번 $\times$ 열 방향 $N$번의 이중 루프(`for r in range(N): for c in range(N)`)를 순회하며 각 위치마다 1번의 곱셈과 1번의 누적 덧셈을 수행해야 합니다. 따라서 총 MAC 연산 횟수는 정확히 $N \times N = N^2$회에 비례하며 시간 복잡도는 **$O(N^2)$**입니다.
   - 실제 측정 결과를 보면, 한 변의 크기 $N$이 `5 → 25`로 **5배** 증가할 때 연산 횟수는 `25 → 625`로 **$5^2 = 25$배** 증가하며, 2D 평균 연산 시간 역시 `0.0051 ms → 0.1226 ms`로 약 **24.0배**(이론값 25배에 매우 근접) 증가했습니다. 마찬가지로 `3×3`(9회) 대비 `25×25`(625회)는 연산 횟수가 약 **69.4배** 증가할 때 소요 시간도 `0.0021 ms → 0.1226 ms`로 약 **58.4배** 증가하여, 실측 연산 시간이 $N^2$에 선형 비례($T(N) \propto N^2$)함을 명확히 입증합니다.
2. **CPU 직렬 처리의 한계와 NPU의 등장 배경**
   - 고작 `25×25` 필터 1개만 연산해도 625번의 곱셈-덧셈이 필요한데, 실제 딥러닝 모델은 수백$\times$수백 크기의 채널·필터를 수천 개씩 합성곱(Convolution)하므로 고화질 이미지 한 장당 수억~수십억 회의 MAC 연산이 발생합니다.
   - CPU처럼 명령어를 하나씩 순차 실행(직렬 처리)하면 $O(N^2)$ 연산량 폭증을 실시간으로 감당할 수 없기 때문에, 수천 개의 MAC 연산기(PE, Processing Element)를 병렬 배치해 한 번에 동시 처리하는 **NPU(Neural Processing Unit)**가 탄생했습니다.
3. **[보너스] 2D 배열 vs 1D 평탄화 배열(길이 $N^2$) 메모리 접근 최적화 효과**
   - Python의 2차원 리스트(`grid[r][c]`)는 바깥 리스트에서 행 참조 포인터를 찾은 뒤 다시 안쪽 리스트에서 열 원소를 찾는 **2단계 간접 참조(Double Indirection)**와 메서드 호출(`get(r, c)`), 이중 루프 분기 비용이 매 원소마다 발생합니다.
   - 이를 길이 $N^2$의 연속된 **1차원 배열(`pattern_1d[i] * filter_1d[i]`)**로 변환하면 단일 루프와 1회 인덱싱만으로 연속된 메모리에 순차 접근(Sequential Access)하게 되어, 동일 입력·동일 반복 횟수 기준 **약 73% ~ 85%의 연산 시간 단축** 효과를 달성했습니다.
